# LURASUPA DC Bot 客戶交付與驗收 SOP

> 文件版本：v1.0（客戶驗收版）<br>
> 發行日期：2026-10-23<br>
> 文件狀態：待客戶驗收<br>
> 適用範圍：目前正式環境中的 Discord、Notion 與公司 Google Drive 流程

## 1. 文件目的

本文件讓客戶不需要閱讀程式碼，也能完成三件事：

1. 理解各角色如何使用系統。
2. 依日常工作順序完成操作。
3. 依驗收表逐項確認功能，留下可追溯的證據並簽核。

本文件是驗收入口。操作細節以「營運操作 SOP」與「藝人操作 SOP」為準；如實際畫面和文件不同，先停止該項驗收並記錄差異，不自行猜測。

## 2. 系統與資料分工

| 系統 | 用途 | 使用原則 |
|---|---|---|
| Discord | 指令入口、通知、藝人回覆、每日提醒、小律查詢 | 藝人不需進入 Notion；管理指令只由營運／控方執行 |
| Notion | 藝人、人員、任務、專案、提交與營運狀態的主要資料來源 | 任務說明寫在任務內頁；欄位用於狀態、日期、關聯和自動化條件 |
| 公司 Google Drive | 藝人交件、修改檔與老師回饋檔 | 交件一律上傳公司 Drive，不在 Discord 傳附件或私人雲端連結 |
| 小律 | 查詢任務與會議紀錄、用一致口吻說明已知資訊 | 不代替營運更改任務；找不到資料時明確說不知道，不自行補造 |

## 3. 角色與責任

| 角色 | 可以做什麼 | 不負責什麼 |
|---|---|---|
| 營運／控方 | 開收集、排課、建立任務、派發、重送、監控、確認結案、處理異常 | 不以 Discord 訊息取代 Notion 的正式狀態 |
| 藝人 | 回填時間、收到任務、回報無法配合、查看早報、上傳交件、查詢自己的任務 | 不直接查看公司 Notion；不在 Discord 交檔 |
| 相關同仁 | 接收與自己有關的任務通知及每日摘要 | 只收到通知，不會因被關聯而取得藝人的收件或交件責任 |
| 負責老師 | 接收課後提醒，到指定論壇發布作業要求與評語 | Bot 不會偵測論壇是否已發文；發布後仍由營運人工確認 |
| 審核人員 | 接收待審核提醒，進行通過、需修改或退件判定 | 若未填或無法聯絡，事項會回到營運內部通知處理 |

> 「關聯藝人」代表需要收到、執行或交件的 Artists；「相關同仁」代表只需知情的 People。兩者不可混用。

## 4. 驗收前準備

- [ ] 指定一位客戶驗收負責人與一位陪測營運人員。
- [ ] 使用明確標示為測試的藝人、人員、任務與月份，不混入真實工作資料。
- [ ] 測試名稱統一加上 `UAT YYYY-MM-DD` 前綴。
- [ ] 確認六個用途頻道可見：營運操作、營運內部通知、公告區、時間管理、任務查詢入口、課程助教。
- [ ] 確認測試藝人 Discord 帳號、相關同仁、老師與審核人員均已綁定正確身分。
- [ ] 確認公司 Drive 測試資料夾可開啟與上傳。
- [ ] 每個案例記錄：時間、任務連結、操作者、實際結果、截圖或訊息連結、Pass／Fail。

> 驗收不得刪除正式任務、正式檔案或正式時段。測試完成後，由營運決定封存或刪除測試資料。

## 5. 日常工作流程

### 5.1 每月收集可配合時間

1. 營運在「時間管理」執行 `/時間資訊蒐集`，設定月份與截止時間。
2. 藝人從私訊或「時間管理」進入 `/管理可配合時間`，新增、補填或刪除時段，完成後送出。
3. 截止前 6 小時與逾期後，尚未完成者各收到一次提醒；若只是測試且不需要回填，營運應取消該次收集。
4. 全員填完時營運收到完成通知；尚未填完的進度也會出現在營運早報。

### 5.2 查共同時段與建立草稿

1. `/時間交集查詢` 只讀取時間池，不會建立或修改任務。
2. `/從時間池建立任務` 會建立尚未派發的 Notion 任務草稿。
3. 營運在 Notion 補齊任務類型、關聯藝人、開始日／截止日、是否需要交件、審核人員、相關同仁與任務內頁內容。
4. TimeTree 如需使用由營運人工維護；Notion Tasks 才是系統正式來源。

### 5.3 派發任務

1. 營運確認任務名稱、類型、對象、日期與內頁內容。
2. 勾選 `Discord 顯示` 後，系統在下一輪檢查內派發，最晚約 30 分鐘。
3. 同一位對象同一輪有多筆任務時合併成一則，仍可逐筆查看。
4. `相關同仁` 收到知會通知；`關聯藝人` 收到可按「收到任務」或「有問題・無法配合」的任務卡。
5. 勾選 `重送通知` 可批次重送；送出後系統會自動取消勾選，避免重複發送。

### 5.4 藝人收到或回報問題

- 按「收到任務」後，Notion 狀態變為 `進行中`，寫入收到時間；卡片收成「任務收好了，小律記下來囉」，同任務舊通知會清除。
- 按「有問題・無法配合」後，原因寫入任務內頁並通知營運。一般任務退回待調整並停止提醒；已逾期任務維持已逾期，只追加回覆供營運處理。
- 已交件或修改中的任務不能用此按鈕退回，藝人需直接聯絡公司。
- 藝人未按收到時，隔日 09:00 先處理未收任務，再顯示當日早報；早報的「我看完了」不等於收到任務。

### 5.5 每日監控與提醒

| 時間／頻率 | 對象 | 內容 |
|---|---|---|
| 每 30 分鐘 | 系統 | 任務派發、重送、逾期與各項背景條件檢查 |
| 每日 09:00 | 藝人、相關同仁 | 個人任務早報；藝人另可確認未收到任務 |
| 每日 09:30 | 營運／控方 | 新逾期、持續逾期、待確認結案、修改逾時、收件與聯絡異常等營運早報 |
| 每日 10:00 | 審核人員、老師、系統 | 待審核催辦、課後老師提醒、Drive 健康檢查 |
| 每 5 分鐘 | 公告區 | 布告欄與本月排程有變才原地更新 |

每日提醒送失敗時，系統會在 30 分鐘後重試，同一天最多三次；已成功收到者不會重複收到。

### 5.6 交件與審核

1. 需要交件的任務必須勾選 `是否開放提交`。
2. 藝人從 `/我的任務` 取得公司 Drive 資料夾，將檔案直接上傳。
3. 上傳後按「我已上傳到 Drive」，任務進入待審核；不要在 Discord 傳附件、貼文字交件或貼私人雲端連結。
4. 審核人員可判定通過、需修改或退件；需修改時應填修改期限，藝人會收到結果並重新交件。
5. 待審核滿 24 小時後，每天 10:00 提醒審核人員；沒有可聯絡的審核人員時通知營運。

### 5.7 課後提醒與公告

- 課程培訓結束滿 2 小時且尚未結案時，負責老師收到提醒；同一位老師同一輪多堂課會合併成一則，之後每天 10:00 提醒，最多 7 天。
- 營運需到論壇人工確認老師已發布作業與評語，再將任務結案。
- 本月排程只納入開始日或截止日在本月、已勾 `Discord 顯示`、類型為通告或演出、且不是已取消／已封存的任務。內容變動時更新原訊息，不新增重複公告。

## 6. 常見異常與處理

| 現象 | 先檢查 | 處理方式 |
|---|---|---|
| 藝人沒收到任務 | Discord 顯示、關聯藝人、Discord User ID、任務是否已結案 | 修正資料後勾 `重送通知`；不要重建同一任務 |
| 同仁沒收到通知 | 是否填在 `相關同仁`、People 是否有 Discord User ID | 修正人員資料後重送 |
| 無法交件 | 是否開放提交、Drive 是否可用、任務是否在可交件狀態 | 先依營運內部警告排除 Drive；不要改用 Discord 收檔 |
| 老師沒收到提醒 | 專案類型、負責老師、截止日、Discord User ID | 補正欄位；必要時由營運人工轉告 |
| 本月公告沒出現任務 | 日期、任務類型、Discord 顯示、取消／封存狀態 | 修正其中不符合的條件，等待下一次同步 |
| Notion 選項警告 | 欄位選項是否被刪除或改名 | 恢復原選項名稱，再重新檢查受影響功能 |
| 每日通知暫時沒送到 | 當日是否已重試、營運內部通知有無錯誤 | 等候自動重試；第三次仍失敗時依內部通知人工處理 |

## 7. 客戶驗收清單

每項完成後勾選結果；若為 Fail，必須留下實際結果、證據與追蹤卡，不能以口頭說明結案。

### A. 時間收集與排課

- [ ] **A1 開啟收集**：建立測試月份收集；藝人看得到入口，營運看得到進度。
- [ ] **A2 回填與修改**：藝人新增、補填、刪除時段後，Notion 反映一致且不誤刪其他時段。
- [ ] **A3 取消測試收集**：取消後不再催促未填者，未來新開收集仍可正常提醒。
- [ ] **A4 時間交集**：查詢只顯示交集，不建立任務；從時間池建立時只產生未派發草稿。

### B. 派發、收到與問題回報

- [ ] **B1 單筆派發**：藝人收到名稱、類型、日期及任務內頁內容，訊息不含 Notion 連結。
- [ ] **B2 收到任務**：按下後狀態、收到時間與卡片收尾皆正確，重啟後不重發舊通知。
- [ ] **B3 合併派發**：同一輪多筆任務合併，可逐筆查看並一次收到。
- [ ] **B4 回報問題**：原因進入任務內頁、營運收到通知、藝人卡片正確收尾。
- [ ] **B5 批次重送**：勾 `重送通知` 後只重送一次並自動取消勾選。

### C. 早報、期限與逾期

- [ ] **C1 藝人早報**：09:00 只發一則，分類、任務詳情與「我看完了」紀錄正確。
- [ ] **C2 未按收到**：先處理未收任務，再出現當日早報；兩種確認不互相混淆。
- [ ] **C3 營運早報**：09:30 的新逾期、持續逾期、待確認結案與異常項目符合 Notion。
- [ ] **C4 逾期規則**：需交件任務過期成為已逾期；不需交件任務維持原狀並等待營運確認。

### D. Drive 交件與審核

- [ ] **D1 開放交件**：藝人取得正確公司 Drive 資料夾，可上傳後回報完成。
- [ ] **D2 待審核**：回報上傳後產生提交紀錄並進入待審核，不接受 Discord 附件替代。
- [ ] **D3 審核結果**：通過、需修改、退件三種結果均通知正確對象並更新狀態。
- [ ] **D4 修改重交**：修改期限、回饋與再次交件不會建立錯誤重複資料。
- [ ] **D5 Drive 健康**：正常時不打擾；模擬失敗時營運一天最多收到一則可操作的警告。

### E. 老師、相關同仁與審核人員

- [ ] **E1 相關同仁**：收到知會通知與每日摘要，但不會被當成藝人要求收件或交件。
- [ ] **E2 老師提醒**：課後滿 2 小時收到合併提醒；營運人工確認論壇並結案。
- [ ] **E3 審核人員**：待審核滿 24 小時後收到每日催辦；無法聯絡時轉營運處理。

### F. 公告與小律

- [ ] **F1 月度公告**：只出現符合四項條件的通告／演出，內容變動時原地更新且不重複。
- [ ] **F2 布告欄**：Notion 內容變動後同步到正確 Discord 頻道。
- [ ] **F3 任務查詢**：小律只回答有依據的任務資訊，不執行修改，也不洩漏其他藝人資料。
- [ ] **F4 會議紀錄查詢**：能回答已記錄內容；沒有資料時明確說找不到。

### G. 安全、權限與可恢復性

- [ ] **G1 角色邊界**：藝人無法使用營運指令，也看不到公司 Notion 連結。
- [ ] **G2 個資邊界**：任一測試帳號只能看到與自己相關的任務與檔案。
- [ ] **G3 重啟恢復**：Bot 重啟後已發送、已收到、已提醒的項目不會無故重送。
- [ ] **G4 錯誤可追蹤**：重要操作有稽核紀錄，失敗時營運能取得足以追蹤的通知。

### 驗收通過條件

- A 到 G 的所有適用案例均為 Pass；不適用項目需寫明理由。
- 每個案例都有可辨識的測試資料與證據。
