# SOP 怎麼寫

SOP 一頁一個主題，依對象分兩個資料夾。之後會轉成互動式 SOP 網站，所以每頁都照這份格式寫。

| 資料夾 | 給誰看 | 網站權限 |
|---|---|---|
| `artist/` | 藝人 | 藝人版、營運版都有 |
| `ops/` | 營運 | 只有營運版（repo 是公開的，營運版網站上線要加登入） |

工程端的設定、`.env`、排查記錄檔放在 [`docs/operations/SETTINGS.md`](../operations/SETTINGS.md)，**不要寫進 SOP**。

## 完整版是產生出來的

`ADMIN_SOP.md`、`ARTIST_SOP.md` 由分頁合併產生，**不要直接改**。改完分頁執行：

```text
.venv/Scripts/python.exe scripts/build_sop.py
```

測試會比對完整版跟分頁，忘了重新產生就會失敗（`tests/test_sop_pages.py`）。

## 每頁開頭的標記

```yaml
---
title: 按鈕與 Notion 欄位的連動      # 頁面標題，也是網站選單上的名字
audience: ops                       # artist 或 ops，要跟資料夾一致
order: 12                           # 同一個資料夾裡的順序，不能重複
rules: [M3-25, M3-24]               # 對應 Notion 規則頁的編號，沒有就寫 []
summary: 一句話說這頁講什麼          # 網站卡片、完整版目錄用
updated: 2026-10-21                 # 最後一次改內容的日期
---
```

標記下面第一行是 `# 標題`，跟 `title` 一樣。頁內小節用 `##`、`###`。

## 固定寫法（網站會變成互動元件）

| 寫法 | 用在哪 | 網站上會變成 |
|---|---|---|
| `> ⚠️ …` | 會出事、不能做的事 | 紅色警告框 |
| `> 💡 …` | 小提醒、背景說明 | 提示框 |
| `> ⏸ …` | 封存中、暫停的功能 | 灰色封存標示 |
| `1. 2. 3.` 編號清單 | 有先後順序的操作步驟 | 可逐步勾選的流程 |
| `<details><summary>問題</summary>答案</details>` | 常見問題、舊版做法 | 點開才看到的段落 |
| `\| 狀況 \| 原因 \| 怎麼做 \|` 表格 | 排查 | 可搜尋的排查工具 |
| ```` ```discord ```` | Discord 訊息、選單的樣子 | Discord 樣式的示意畫面 |
| ```` ```notion ```` | Notion 欄位或內頁裡會出現的文字 | Notion 樣式的示意 |
| ```` ```text ```` | 資料夾路徑、指令 | 等寬文字 |
| ```` ```mermaid ```` | 示意圖：流程（`flowchart`）、誰對誰做了什麼（`sequenceDiagram`）、狀態怎麼變（`stateDiagram-v2`） | 畫成圖，顏色跟著深淺色模式；GitHub 上也看得到 |

## 流程頁的固定版型（營運）

營運 SOP 依「工作流程」分頁，每一頁照這個順序寫：

1. **什麼時候用**：一句話情境
2. **💡 一句話看懂**：整條流程濃縮成一句
3. **示意圖**：能畫就畫
4. **開始前要準備好**：`| 要準備的 | 在哪裡設 | 少了會怎樣 |`
5. **每個階段**：先寫「你要做的」或「藝人做的」，再用 `| 系統 | 發生什麼 |` 表格分 📒 Notion（哪個欄位變成什麼值）、💬 Discord（誰收到什麼）、📁 Drive（建了什麼）
6. **做完怎麼確認成功**：去哪裡看、應該看到什麼
7. **出錯怎麼辦**：`| 狀況 | 原因 | 怎麼做 |`

欄位名稱、選項值一律照 Notion 實際的字寫在 `` ` `` 裡，說明用白話。藝人版不寫欄位名稱，只寫藝人看得到的東西。

其他原則：

- 編號清單只用在真的有順序的步驟。
- 用營運、藝人看得懂的話寫，不寫函式名稱、commit 編號。
- 頁與頁之間用「見『頁面標題』」互相指，不要寫「見上一節」「見下方」，網站上頁面順序可能不一樣。
- Discord 範例用真實的格式，資料是範例的話寫在範例前面。
