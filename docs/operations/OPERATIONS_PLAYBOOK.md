# 營運 SOP

## 會議紀錄維護與小律查詢

會議結束後，控方或老師手動維護 `課程與會議記錄`：

1. 整理重點、要求與作業說明。
2. 關聯參與藝人、老師、Project 與 Task。
3. 確認內容沒有公司內部敏感資訊。
4. 依實際性質設定 `會議類型`。
5. 確認後勾選 `藝人可見`，才會提供給 Discord `課程助教` 頻道的小律查詢。

未勾選 `藝人可見` 的紀錄，Bot 不會交給藝人或 LLM；`會議類型` 屬於 `課程`、`課程會議` 的紀錄一律不提供給藝人（`A&R 會議` 只要勾了 `藝人可見` 就會提供，不想給藝人看的不要勾），即使勾選 `藝人可見` 也一樣。

藝人如何使用小律、附件檔案怎麼處理、LLM 供應商與重試行為，權威說明在 [DISCORD_COMMANDS.md「會議秘書小律」](DISCORD_COMMANDS.md#會議秘書小律)，這裡不重複描述。

這份文件給控方照流程操作。  
原則：藝人填的是「可配合時間」，正式安排要由營運建立 `Project` / `Task` 後才成立。

Discord 頻道與 slash command 對應總表請看 [DISCORD_CHANNELS.md](DISCORD_CHANNELS.md)。

## Discord 頻道分工

目前建議六個用途頻道：

| 頻道 | 用途 |
|---|---|
| `公告區` | 公開類型 Task、月度收集公告、排課公告（唯讀；未設定時公告發到時間管理） |
| `時間管理` | 藝人回報與管理月度可配合時間 |
| `任務查詢入口` | 藝人查詢自己的任務並提交作業 |
| `營運內部通知` | Bot 自動推送任務、審核、排課、SLA 與回填通知（控方限定） |
| `營運操作` | 控方執行 slash command 與手動補救操作（控方限定） |

這裡的頻道名稱代表用途；換到其他公司時可以沿用相同用途命名，但 `.env` 裡的頻道 ID 需要改成該公司 Discord server 的實際 ID。

操作原則：

- 控方在 `營運操作` 建立時間資訊蒐集；藝人在 `時間管理` 回報與管理可配合時間。
- `任務查詢入口` 只保留藝人的 `/我的任務`，提交功能由該入口內的按鈕進入。
- 時間池比對、任務總覽、重送與審核等控方工作放在 `營運操作`。
- 藝人完成回填、提交、拒絕任務與審核逾期等自動通知固定放在 `營運內部通知`。
- 每天 10:00 的 Drive 健康檢查失敗時也發在 `營運內部通知`（🔴 開頭，附修法）；看到就當天處理，否則藝人交不了件。
- `.env` 的 `TASK_CHANNEL_ID` 有設定時，只有 `/我的任務` 使用任務查詢入口。
- `.env` 的 `SCHEDULE_CHANNEL_ID` 有設定時，藝人時間管理只能在時間管理使用。
- `.env` 的 `ADMIN_COMMAND_CHANNEL_ID` 有設定時，管理端工作指令只能在營運操作使用；留空時沿用 `ADMIN_NOTIFY_CHANNEL_ID`。
- 若要讓錯頻道完全看不到不相關 slash command，請在 Discord App / Integration 的 command permission 再設定頻道可見性。

## 任務派發與收件確認 SOP

1. 控方在 Notion `Tasks` 建立或更新任務。
2. 依角色填寫任務相關對象：執行／確認／交件的藝人填 `關聯藝人`；老師或公司同仁的知會對象填 `相關同仁`。兩欄可以同時填，不能用單一 `相關人士` Relation 取代。
3. 設定 `任務狀態=尚未開始`，並勾選 `Discord 顯示`。
4. 確認 `Discord 通知時間`、`Discord 收到時間` 欄位已存在。
5. Bot 會私訊關聯藝人（以及有填的 `相關同仁`），顯示任務名稱、類型、截止日與任務內頁 `任務說明` 區塊的內容。
6. 藝人按「收到任務」後，Task 轉為 `進行中`，控方可在 Notion 或 Audit Log 確認收件時間。同一任務之前的通知會全部改成「✅ 已收到」並拿掉按鈕。相關同仁沒有按鈕，也不需要回覆。
7. 每個任務都要個別按「收到任務」；Bot 每 12 小時固定掃描一次，當下所有未確認任務都會再次私訊提醒。這項催辦只針對藝人。

藝人回報無法配合時：

1. 藝人按「有問題／無法配合」並填寫原因。
2. Bot 將原因追加到任務內頁的「藝人回覆」區塊，通知控方，並把任務退回 `尚未開始`。
3. Bot 同時取消 `Discord 顯示` 並清空舊通知時間，暫停對藝人重送。
4. 控方修改任務內容、時間或對象後，重新勾選 `Discord 顯示`。
5. 下一輪背景檢查會重新派發完整任務通知，藝人需重新按「收到任務」。

若沒有收到通知：

1. 確認 Task 有勾選 `Discord 顯示`。
2. 確認 `關聯藝人` 對應到 Artists 的 `Discord User ID`。公司同仁則確認 `相關同仁` 有填、People 有 `Discord User ID`。
3. 確認 `Discord 通知時間` 為空，或由控方在任務頻道使用 `/任務通知重送`。
4. 若 Artist 沒有 Discord User ID，Bot 會在控方通知頻道提醒，補齊後再重送。

首次啟用通知功能時，Bot 不會回頭轟炸既有任務；測試時請建立一筆新的測試任務。

一次要重送很多筆時，在 Notion Tasks 勾 `重送通知`（可批次勾選）。下一輪背景檢查會逐筆重送、自動取消勾選，並在 `營運內部通知` 發一則結果摘要；沒勾 `Discord 顯示` 或已結束的任務會略過。

## 提醒與催辦 SOP

| 項目 | 對象 | 時間 |
|---|---|---|
| 截止前提醒 | 藝人（＋相關同仁） | 死線前 5 天、3 天各一次，`提醒規則` 勾的再加。已發過的記在 `.state/`，重啟 bot 不會重發 |
| 逾期升級 | 藝人＋控方 | 過了死線的下一輪，任務改 `已逾期`。控方改回 `進行中` 但沒延期，下一輪會再通知一次 |
| 每日催辦 | 藝人：`已逾期`、`需修改`；審核人員：`待審核` 滿 24 小時 | 每天 10:00，每人一則彙整，不帶按鈕 |
| 修改期限逾時 | 控方 | 過了 `修改期限` 還在 `需修改`，通知一次 |
| 課後提醒老師 | `負責老師`（聯絡不到就控方） | 課程培訓類結束 2 小時後，之後每天 10:00，最多 7 天；同一堂課只發一則 |
| 發文待確認發布 | 控方 | 每週一 10:00，列出發文類停在 `已完成` 超過 3 天的任務，提醒確認發布後改 `已完成發文` |

時間都可以在 `.env` 調整（`DAILY_NAG_HOUR`、`TEACHER_REMINDER_*`、`PUBLISH_CONFIRM_DIGEST_*`），改完重啟 bot。

## 主流程：每月時間收集到排程

1. 控方在例會或月度排程前確認下個月需要安排的方向。
2. 控方在 `營運操作` 執行 `/時間資訊蒐集 月份:YYYY-MM`。
3. 藝人透過公告、DM 或 `/管理可配合時間` 回填月度可配合時間。
4. 藝人把相同時段的日期加入一組；不同時段繼續加入下一組。
5. 藝人可用「管理全部已選」進入任一草稿，再修改組內單日、修改整組或移除草稿，最後按「檢查全部時段」及「全部確認送出」。
6. Bot 會通知控方個別藝人完成狀態。
7. 全員填完後，Bot 會通知控方可以執行 `/從時間池建立任務`。

### 時間池比對後的安排分流

`/從時間池建立任務` 找到共同空檔後，控方先勾選候選，再選安排類型：

若選錯，候選時段可返回藝人選擇；任務類型可返回候選時段；課程類型、Project、老師選單也都能返回上一層。Modal 取消後可以在原選單重新選擇，不必重打 slash command。

所有主要多步驟流程都採相同規則：第一層可取消、下一層可返回。月度時間可先累積多組草稿，需在整批總覽按「全部確認送出」才寫入 Notion；刪除可配合時間與 `/任務通知重送` 也必須二次確認。

1. **課程**：選課程類別、課程培訓 Project、老師與課程名稱，Bot 直接建立一筆 `Tasks` 的 `課程時間&作業繳交`；候選時段寫在任務說明，正式時間由營運填回 Task。
2. **錄音**：Bot 建立隱藏 Task 草稿，控方補齊內容後發布。
3. **通告**：Bot 建立隱藏 Task 草稿，控方補齊內容後發布。
4. **其他**：Bot 建立隱藏 Task 草稿，控方依事項性質補齊內容。

課程名稱由控方在 Discord 輸入，不再由 Bot 自動組合藝人與月份名稱。
7. 控方用 `/從時間池建立任務` 查看共同空檔。
8. 控方依結果在 Notion 建立或更新 `Project` / `Task`。

## 每月時間收集 SOP

建議節奏：

- 每月固定日期發一次，例如每月 25 號前收集下個月。
- 需要臨時更新時，可以再發一次 `/時間資訊蒐集`，但不是必要。
- 如果只是個別藝人補填或修改，請藝人用 `/管理可配合時間`。

操作：

1. 執行 `/時間資訊蒐集`。
2. 填 `月份`，例如 `2026-08`。
3. `截止天數` 預設用 1，代表 24 小時內回填。
4. `說明` 只放必要補充，例如「請優先填週末」。
5. 發出後確認排課頻道有公告。
6. 如果有藝人 DM 失敗，手動提醒他到頻道公告或使用 `/管理可配合時間`。
7. 藝人可跨日期頁選完整月份；每組日期套用同一時段，不同時段再加入下一組。
8. 所有組別暫存在 Bot；可從「管理全部已選」進入任一組，再選組內某一天修改。該日會自動拆出，同組其他日期保持原設定。
9. 按「全部確認送出」前不會寫入 Notion；取消單組修改不會刪除原組。
10. Bot 使用 `Asia/Taipei` 系統日期隱藏今天以前的日期；這是本機時間判斷，不會消耗外部 API 或 AI token。

## 藝人修改時間 SOP

標準流程：

1. 藝人執行 `/管理可配合時間`。
2. 從總覽選擇月份，再選擇要刪除的錯誤時段。
3. Bot archive Notion `Availability Slots` 對應資料。
4. 在同一入口按「新增／補填日期」。
5. 重新填正確時段。

注意：

- 不需要請控方重發公告。
- 刪除是同步 Notion archive，不是只在 Discord 隱藏。
- 修改後若有重複或重疊，整批送出時會自動整理。
- 若所選時間撞到已有明確時間的正式 Task，Bot 會在整批總覽顯示實際保留與排除時段；藝人確認後才寫入。整段都被占用時必須返回修改。

## 時間池比對 SOP

使用時機：

- 藝人已回填月度可配合時間。
- 控方要找多位藝人的共同空檔。
- 例會後要安排課程、錄音、通告或其他事項。

操作：

1. 執行 `/從時間池建立任務 月份:YYYY-MM 時長分鐘:N`。
2. 選要一起比對的藝人。
3. 查看依需求時長切好的候選時段。
   - Discord 每頁最多 25 個候選；用「上一頁／下一頁」查看全部候選，已選項目會保留。
4. 若有人未填，先請該藝人用 `/管理可配合時間`。
5. 若沒有共同空檔，縮短時長、改選藝人，或請藝人補更多時段。
6. 課程會直接建立 `Discord 顯示=false` 的 Task；其他類型也建立 `Discord 顯示=false` 的 Task 草稿。候選時段先寫在任務說明，正式時間由控方人工協調後回填 Task。
7. 控方在 Notion 補齊內容、地點與正式時間；確認無誤後勾選 `Discord 顯示=true`，Bot 自動通知藝人。

只想先看藝人共同空檔、還不確定要不要建立任務時，可以用唯讀的 `/時間交集查詢`；細節見 [DISCORD_COMMANDS.md](DISCORD_COMMANDS.md)。

通告、演出等公開類型會同步發到公告區；課程、錄音與其他任務只通知關聯藝人。公開類型可由 `.env` 的 `PUBLIC_TASK_TYPES` 調整，值必須是 Notion `任務類型` 既有的選項。

公告區每個月也會有一則固定的「本月排程」，列出當月已派發的公開類型任務；每 5 分鐘檢查，內容有變就更新同一則，不會洗版。若公告被手動刪除，下一輪會自動補發，即使排程內容未變。

SLA：藝人預設 24 小時回填；截止後半天仍未比對會提醒控方；流程超過 48 小時升級，72 小時提示候選可能失效。

### TimeTree 補登

TimeTree 沒有納入 API 自動同步。正式 Task 與 Discord 通告確認後，由控方人工補登 TimeTree；TimeTree 是過渡期展示／行事曆，不是 Bot 的正式資料來源。若 TimeTree 與 Notion 不一致，以 Notion Tasks 為準並人工修正 TimeTree。

判讀：

- 候選時段已依這次需求時長切好；例如需要 1 小時，就會顯示一小時一列。
- 候選起點每 30 分鐘切分，例如 `13:30-14:30`、`14:00-15:00`。
- 比對會扣除 Tasks 中已填寫的正式精準時間。

## 例會後建立 Project / Task

例會確認的正式事項，不應寫成 Availability Slot。

建議做法：

- 有上層企劃、活動、作品、月度任務時，先建 `Project`。
- 具體要做的事情建 `Task`。
- Task 要填 `任務類型`、`任務狀態`、`開始日`、`截止日`、`關聯藝人` 或 `關聯專案`。
- 課程任務固定選 `任務類型=課程時間&作業繳交`，再填 `課程類別`，並以 `負責老師` 關聯 People 中的老師或公司成員。
- 只有要讓藝人在 Discord `/我的任務` 看到的任務，才勾 `Discord 顯示`。
- 課程剛建立時先勾 `Discord 顯示`、保持 `是否開放提交` 未勾，讓藝人先收到課程安排；課程結束後由老師／控方補齊作業要求、`審核人員` 與 `提交期限`，最後再勾 `是否開放提交`，Bot 會自動發送第二次課後作業通知。
- `開始日／截止日` 保留正式上課時間；不要把 `截止日` 改成作業期限。第一次繳交期限直接在 Notion 的 `提交期限` 設定。
- 審核結果為 `需修改`／`退回` 時，由審核人在 Discord 輸入 1～7 天，Bot 寫入 `修改期限`。重新提交後會清除本輪修改期限並轉回 `待審核`。
- 一般任務若已具備提交要求，也可直接勾 `是否開放提交`。
- 課程類（專案類型 `課程培訓`）結束後，Bot 會自動私訊 `負責老師` 到論壇發布作業要求與評語，每天 10:00 一次、最多 7 天。**控方要手動到論壇確認老師已發布，再把任務結案；Bot 不偵測論壇貼文。** 結案後提醒才會停止。老師沒有 Discord ID 時，提醒會發到 `營運內部通知`。

交件只有一種方式（2026-10-11 起）：上傳到 Bot 提供的公司 Drive 資料夾。`提交方式` 欄位已停用，不需要設定。
藝人執行 `/我的任務` → `提交任務`、選任務後，Bot 提供這次提交的 Drive 資料夾；藝人上傳後按「我已上傳到 Drive」，Bot 驗證入口建立後的新檔案並完成提交。不接受藝人自己的雲端連結、文字表單或截圖佐證。
完整規則見 [SUBMISSION_FLOW.md](SUBMISSION_FLOW.md)。

課後作業通知由背景輪詢觸發，間隔讀取 `.env` 的 `REMINDER_INTERVAL_MINUTES`。若已勾開但尚未收到，先確認 Task 已勾 `Discord 顯示`、有關聯藝人，再查看 Bot log 與 `Audit Log`。

## 提交審核 SOP

使用時機：

- 藝人提交作業／作品後，Task 已轉為 `待審核`。
- 控方或老師要回覆 `通過`、`需修改` 或 `退回`。

Discord 審核：

1. 控方在 `營運內部通知` 執行 `/審核提交`。
2. 選擇待審核提交。
   - 在 `審核人員` 選 `🧑🏻‍🏫 成員・老師・合作方` 中 `身份類型=公司成員` 的人；背景提醒會優先通知指定人員，未設定時仍由控方審核。
3. 先確認 Bot 顯示的 Drive 連結、Notion 提交頁與關聯任務連結。
4. 選 `通過`、`需修改` 或 `退回`。
5. 填寫給藝人的回饋，可留空。
6. Bot 會更新 Notion，並私訊藝人審核結果。
7. `需修改`／`退回` 時輸入 1～7 天修改期限；若老師有批改檔按 `附批改檔`，否則按 `不需補批改檔`。

Notion 手動審核：

1. 在 `Submissions & File Index` 找到最新版提交。
2. 將 `審核狀態` 改為 `通過`、`需修改` 或 `退回`。
3. 填 `審核回饋`、`審核者` 或 `審核來源` 任一欄。
4. Bot 背景 loop 會通知藝人，並寫入 `審核通知時間`。

注意：

- `通過` 會把 Task 轉 `已完成`。
- `需修改` / `退回` 會把 Task 轉 `需修改`，藝人可重新 `/我的任務` → `提交任務`。
- Bot 會把同一次回饋的多個檔案歸檔到 `藝人專區/專案名稱/YYYY.MM.DD_任務名稱/老師回饋/老師回饋_YYYY.MM.DD_ver.N/`，並把連結併入 `審核回饋`。
- 超過 10MB 的批改檔，Bot 會提供老師回饋 Drive 資料夾；老師上傳後按 `貼 Drive 連結補回饋` 補到 Notion `審核回饋`。按鈕訊息消失的話，3 小時內在同一頻道打一句話就會重新出現。
- 待審核提交不設固定審核期限；提交滿 24 小時未審核後，列入每天 10:00 的每日催辦，私訊指定審核人員（沒填或聯絡不到就發到 `營運內部通知`），直到審核完成。
- 如果只改 `審核狀態` 但沒有任何回饋／來源欄位，Bot 會視為歷史資料整理，不主動通知。
- 如果 Discord 顯示「審核寫入 Notion 失敗」，先到 `Submissions & File Index` 確認是否已有
  `審核回饋`、`審核者`、`審核來源`、`審核通知時間` 四個欄位；缺任一個都可能導致寫入失敗。

排程判斷：

- `錄音`、`演出`、`會議溝通`，以及有 `課程類別` 的 `課程時間&作業繳交`，且有明確開始 / 結束時間，會被視為硬性佔用。
- 作業、創作交付、企劃、行政、發布上架等只做提醒，不直接封鎖整天。
- Project 日期只做營運提醒，不直接封鎖藝人整段時間。

## 哪些是正式行程

正式行程：

- Notion `Tasks` 中已安排且有明確時間的硬性任務。
- 控方在 Notion 明確建立的正式 Project / Task。

不是正式行程：

- `Availability Slots` 的月度可配合時段。
- 藝人補填的空檔。
- `/從時間池建立任務` 顯示的候選共同空檔。

## 常見問題排查

### 先看 bot 記錄檔

任何「❌ …失敗，請稍後再試」都先看 `kari-kari-ai-ops/logs/bot.log`（2026-10-18 起；5MB 輪替、保留 5 份）。畫面上的錯誤訊息是給使用者看的，真正原因（例外與行號）只在這個檔案裡。搜尋畫面上那句話的關鍵字（例如「讀取藝人任務失敗」），下面幾行就是原因。

bot 每次啟動也會比對 Notion 選項（`services/schema_check.py`）。Notion 的篩選只要帶到不存在的選項，整個查詢就失敗，所以刪掉或改名「任務狀態」「審核狀態」這類選項，會讓對應功能整個停擺；對不上時 `營運內部通知` 會收到 ⚠️ 警告。

### 藝人看不到 `/我的任務`

檢查：

- 是否在 `任務查詢入口` 頻道使用。
- `Artists` 是否填 Discord User ID。
- `Tasks` 是否關聯該藝人。
- `Tasks` 是否勾 `Discord 顯示`。
- 任務狀態是否已完成、已取消或已封存。

### 可排課藝人是 0 位

檢查：

- `Artists` 是否有 Discord User ID。
- `合約狀態` 是否為 `暫停` 或 `封存`。
- Notion integration 是否有 Artists 資料庫權限。

### 時間池比對沒有共同空檔

檢查：

- 是否選錯月份。
- 是否有人未填。
- 是否時長太長。
- 是否 Tasks 已佔用大部分時間。

### 藝人說填錯時間

處理：

1. 請他開啟 `/管理可配合時間` 並選擇月份。
2. 在同一入口刪除錯誤時段，再補填正確時段。
3. `/從時間池建立任務` 會在比對前自動整理被選藝人的時間池。

### 管理端指令看不到

檢查：

- 使用者是否有 Discord Administrator 權限。
- Bot 是否已重啟並同步 slash commands。
- Bot 是否仍在該 guild 裡。

## 營運原則

- Availability Slots 只是時間池，不是承諾保留。
- 正式安排一律回到 Project / Task。
- 有衝突時，以 Notion 正式安排為準。
- 改時間要保留紀錄，不直接手動刪資料庫 page。
- Bot 寫入失敗時先看 console log，再看 Audit Log 是否有錯誤紀錄。
- 課程安排後不再有自動老師確認表單；正式時間如有異動，由控方與老師人工協調後直接在同一筆 Task 更新開始／結束時間。
