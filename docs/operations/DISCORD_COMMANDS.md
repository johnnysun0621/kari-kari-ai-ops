# Discord 指令與流程完整參考

系統所有進入點的完整清單：**11 支 slash command、8 項背景自動化、按鈕與表單互動**，每個流程標明讀寫哪些 Notion 欄位。

給營運照步驟操作的版本在 [控方 SOP](../sop/ADMIN_SOP.md) 與 [藝人 SOP](../sop/ARTIST_SOP.md)；這份是查細節與排查問題用。

### 非指令觸發的流程

| 流程 | 觸發 | 間隔 |
|---|---|---|
| 任務派發通知 | Task 勾 `Discord 顯示` | 30 分鐘輪詢 |
| 課後作業通知 | Task 再勾 `是否開放提交` | 30 分鐘輪詢 |
| 未確認任務重送 | 藝人未按「收到任務」 | 每 12 小時 |
| 截止前提醒 | 依 `提醒規則` | 30 分鐘輪詢 |
| 逾期升級 | 過截止日 | 30 分鐘輪詢 |
| 審核催辦 | 提交滿 24 小時未審 | 每 12 小時 |
| 修改期限提醒 | 接近 `修改期限` | 30 分鐘輪詢 |
| 月度時間池提醒 | 收集截止前後 | 30 分鐘輪詢 |
| 排課 SLA | 超過 48／72 小時 | 30 分鐘輪詢 |
| 布告欄同步 | 自動 | 5 分鐘 |
| 小律問答 | `AI_CHANNEL_ID` 頻道收到訊息 | 即時 |

輪詢間隔由 `REMINDER_INTERVAL_MINUTES` 控制（預設 30），布告欄由 `BULLETIN_SYNC_INTERVAL_MINUTES`（預設 5）。

### 時間設定總覽

**可從 `.env` 調整**（改完重啟生效）

| 設定 | 預設 | 用途 |
|---|---|---|
| `REMINDER_INTERVAL_MINUTES` | 30 分 | 背景主迴圈；所有自動通知的檢查頻率 |
| `TASK_ACK_REMINDER_HOURS` | 12 小時 | 未按「收到任務」的重送間隔 |
| `REMIND_BEFORE_DEADLINE_HOURS` | 6 小時 | 月度收集截止前催填時機 |
| `REVIEW_REMINDER_AFTER_HOURS` | 24 小時 | 提交後多久列入每日催辦 |
| `DAILY_NAG_HOUR` | 10 | 每日催辦與課後提醒老師的整點 |
| `TEACHER_REMINDER_AFTER_HOURS` | 2 小時 | 課程結束後多久第一次提醒老師 |
| `TEACHER_REMINDER_MAX_DAYS` | 7 天 | 提醒老師最多幾天，之後改通知控方 |
| `PUBLISH_CONFIRM_DIGEST_WEEKDAY`／`_HOUR`／`_AFTER_DAYS` | `0`／`10`／`3` | 發文待確認發布彙整：星期幾（`daily`＝每天）、幾點、截止日過幾天才列入 |
| `HARD_BLOCK_TASK_TYPES` | 錄音、演出、會議溝通 | 有起訖時間時硬擋藝人時段的任務類型 |
| `NO_OVERDUE_PROJECT_TYPES` | 課程培訓 | 不判逾期的專案類型 |
| `FILE_UPLOAD_WAIT_MINUTES` | 180 分 | Drive 上傳有效期 |
| `BULLETIN_SYNC_INTERVAL_MINUTES` | 5 分 | 布告欄同步 |
| `DEFAULT_REMINDER_RULES` | `5 天前,3 天前` | 每個任務一律套用，與 `提醒規則` 取聯集（2026-10-03 起） |
| `APPROVAL_LEAD_DAYS` | `5` | `提前交件` 任務沒填 `提交期限` 時，截止日往前推幾天當交件死線 |

`tests/test_config.py::TestOperationalTimings` 會驗證這些值確實從環境變數讀取，防止被改回寫死。

**仍寫死在 `config.py`**

| 常數 | 值 | 用途 |
|---|---|---|
| `sla_hours` | 48 小時 | 排課流程升級通知 |
| `sla_hard_limit_hours` | 72 小時 | 候選時段可能失效提示 |
| `default_fill_deadline_hours` | 24 小時 | `/時間資訊蒐集` 的 `截止天數` 預設（下指令時可改）|

**操作畫面逾時**（`discord.ui.View` 的 timeout）

| 畫面 | 秒數 |
|---|---|
| 一般選單、任務／審核清單、候選時段 | 600（10 分）|
| 審核動作、批改檔選擇、伺服器初始化 | 300（5 分）|
| 任務重送確認 | 180（3 分）|
| 等待檔案上傳 | `FILE_UPLOAD_WAIT_MINUTES × 60` |
| 小律「回報問題」 | 86400（24 小時）|

**技術限制**

| 項目 | 值 | 位置 |
|---|---|---|
| Notion 請求間隔 | 0.34 秒（約 3 req/s）| `notion_api._MIN_REQUEST_INTERVAL` |
| 小律 LLM 逾時 | 45 秒 | `course_qa.COURSE_QA_TIMEOUT_SECONDS` |
| 小律重試上限 | 2 次 | `course_qa.COURSE_QA_MAX_ATTEMPTS` |
| 小律上下文 | 16,000 字 | — |
| Discord 互動回應 | 3 秒（超過需 defer）| Discord 平台限制 |
| Discord 單則訊息 | 2000 字（實作留 1900 buffer）| `ui_text.DISCORD_MESSAGE_LIMIT` |
| Drive 檔案搜尋回溯 | 10 分鐘 | `drive_api` |

### 互動返回規則（所有多步驟流程共通）

- 第一層有「取消」，第二層以上有「返回上一步」
- **返回與取消都不寫入 Notion**
- Modal 不能放返回按鈕；關掉 Modal 後原選單仍可操作，也不寫入
- 已完成提交、審核、建立 Task 之後不提供假返回
- 清單過長時自動分頁：「上一頁／下一頁」翻頁，另有**跳頁下拉**可直接指定頁數
  - 跳頁選單的每個選項會標示該頁內容（候選時段顯示日期範圍、任務清單顯示分區名稱）
  - 只有一頁時整個下拉不出現；頁數超過 25 時取目前頁附近的一段，並固定保留第一頁與最後一頁
  - 共用實作在 `cogs/paging.py` 的 `PagedTextView`

## 藝人端

### `/管理可配合時間`

查看、補填、修改、刪除自己的月度可配合時間。

**參數**：`月份`（選填，留空先看跨月總覽）

**讀**
- `Artists`：用 Discord User ID 找到藝人 → 取 `藝人名稱`、`合約狀態`
- `Availability Slots`：該藝人所有未來時段
- `Tasks` / `Projects`：送出時檢查正式安排衝突

**流程**

```
選月份
 └─ 勾日期（可多選）→ 設時段 → 加入一組
     └─ 繼續選日期 → 再加一組…
         ├─ 管理全部已選 → 修改單日／修改整組／移除
         └─ 檢查全部時段 → 列出實際保留內容
             └─ 全部確認送出 ← 到這一步才寫 Notion
```

**寫**（按「全部確認送出」時）

`Availability Slots` 每筆新增：
`可用時段名稱`、`填寫藝人`、`填寫人名稱`、`身份`=藝人、`來源`=Discord、`可用開始時間`、`可用結束時間`、`提交時間`、`是否逾期提交`、`備註`

備註慣例：`收集月份：YYYY-MM`、`收集性質：月度可配合時段`、`藝人備註：…`

刪除時 **archive**（不硬刪）。整理重疊時更新 `可用開始時間`／`可用結束時間`。動作寫 `Audit Log`。

**注意**
- 日期選單依 Bot 主機的台北系統日期，今天以前不顯示
- 單日修改會自動從原組拆出，同組其他日期保留
- 整段都被正式任務佔用時不允許送出

### `/我的任務`

查看自己未完成、即將到期、逾期、待審核的任務。**唯讀。**

**讀**
- `Artists`：Discord User ID → 藝人
- `Tasks`：關聯該藝人且 `Discord 顯示`=true 的任務

**顯示分區**：🔴 已逾期 ／ 🛠 需修改 ／ ⏰ 三天內截止 ／ 📋 進行中・待提交 ／ 📮 待審核

有可提交任務時顯示「提交任務（N）」按鈕。任務多時自動分頁，分區跨頁會重印標題並標示「（續）」。
跳頁下拉的標籤顯示該頁涵蓋的分區（例如「🔴 已逾期、🛠 需修改」），方便直接跳到要處理的那一段。

### 提交任務（`/我的任務` 內的按鈕）

**進入條件**：Task 同時滿足 `是否開放提交`=true、`Discord 顯示`=true、關聯該藝人、狀態不在 `已完成`／`已取消`／`已封存`／`待審核`。

**流程**

```
提交任務
 └─ 第一畫面：列出可提交任務與任務說明摘要
     └─ 選任務 → 給這次提交的公司 Drive 資料夾連結 → 上傳 → 按「我已上傳到 Drive」
        （只有這一種交法；`提交方式` 欄位已從 Notion 刪除）
```

**寫**

`Submissions & File Index` 新增：
`提交名稱`、`提交藝人`、`關聯任務`、`提交來源`=Discord、`提交類型`、`檔案類型`（依任務類型自動對應）、`審核狀態`=待審核、`權限等級`=藝人本人、`是否最新版`=true、`提交時間`
另寫 `Drive URL`、`Drive File ID`、`原始檔名`、`檔案大小 MB`

同時：
- 同任務舊提交 `是否最新版` → false
- `Tasks`：`任務狀態` → `待審核`、`最新提交 URL` 回寫
- 單一藝人任務首次提交時，把任務資料夾連結回寫 `Google Drive Folder`；多人任務則寫進任務內頁的「Drive 資料夾索引」區塊

**檔案路徑**
`藝人專區 / 任務類型 / YYYY-MM / YYYY.MM.DD_任務名稱 / 任務名稱_YYYY.MM.DD_ver.N`
顯示檔名自動加前綴 `{藝人名稱}_{任務名稱}_{原檔名}`。系統不接收 Discord 附件。

### 任務通知與提醒的持久化按鈕

**重啟 Bot 後仍可點**（`DynamicItem`，在 `bot.py` 註冊）。

| 按鈕 | 出現在 | 寫入 |
|---|---|---|
| **收到任務** | 派發通知、未確認重送 | `Discord 收到時間`、`任務狀態` → `進行中` |
| **有問題・無法配合** | 派發通知、未確認重送 | 原因追加到任務內頁的「藝人回覆」、`任務狀態` → `尚未開始`、`Discord 顯示` → false、清空兩個 Discord 時間欄位與 `提醒確認(From 藝人)`，並通知控方 |
| **收到通知** | 截止前提醒（3 天前／1 天前／當天） | `提醒確認(From 藝人)` 追加 `階段｜時間｜藝人名`。不改任務狀態。逾期通知沒有這顆 |

> 原本派發通知還有第三顆「查看任務內容」連結按鈕，2026-09-18 移除——藝人端零 Notion 入口（見 CLAUDE.md 鐵則 7）。任務說明改為直接寫在通知訊息裡。

### 小律問答（`課程助教` 頻道）

在 `AI_CHANNEL_ID` 頻道**直接輸入訊息**即可，不需指令或 mention。

**流程**：Bot 建立只對該藝人開放的私人 Thread → LLM 判斷檢索方向 → 回答並附來源 → 附「回報問題」按鈕

**可回答的範圍**（三個條件同時成立）
1. `參與藝人` 關聯該藝人，或由 Tasks 的 `課程與會議記錄`／`關聯專案` 反向追溯到他
2. `藝人可見` 已勾選
3. `會議類型` **不在** `QA_HIDDEN_MEETING_TYPES` 排除清單內

**附件**：新 Thread 首次先列出有附件的頁面與檔名，藝人指定後才把該附件納入檢索。支援 PDF／DOCX／PPTX／XLSX 與純文字。

**寫**：只有藝人主動按「回報問題」時，才在佈告欄建一筆 `類別`=🙋 使用回饋、`狀態`=未處理。不保存提問全文。

`未簽`／`暫停`／`封存` 的藝人不能使用。每次提問重新同步 Notion，失敗才用上次成功的快取。

## 控方端

### `/時間資訊蒐集`

發起某月份的可配合時間收集。

**參數**：`月份`、`截止天數`（預設 1）、`說明`（選填）

**讀** `Artists`：找可排課藝人（有 Discord User ID、`合約狀態` 為 `已簽約` 或 `洽談中`）

**動作**：`公告區` 發公告並 mention → 私訊每位藝人 → 寫 `Audit Log`

背景流程會追蹤未填藝人並催收，全員完成時通知控方。

---

### `/取消時間蒐集`

停止進行中的月度時段收集。誤觸 `/時間資訊蒐集` 或改變主意時使用。

**流程**：列出進行中的收集（月份／截止時間／已填幾位）→ 選一筆 → 確認

**動作**
- `time_collection.deregister_collection()` — 停止催填與逾期通知
- `scheduling_sla.deregister_collection()` — 停止 48／72 小時的排課 SLA 升級
- 寫 `Audit Log`（操作類型＝更新，before 記錄原截止與進度）

> **兩個狀態存放處都要清**。收集同時登記在 `time_collection` 與 `scheduling_sla`，
> 只清前者的話，SLA 提醒還是會在 48 小時後發出。

**不會做的事**
- 不刪已發出的公告與私訊（Discord 端要手動處理）
- **不刪藝人已填的時段**，那些資料保留、仍可用於排課

進度讀取失敗時仍可取消——那正是最需要這支指令的情況。

沒有進行中的收集時會直接說明：收集在全員填完或逾期通知發出後會自動結束，不需手動取消。

### `/時間交集查詢`

**唯讀**查看藝人共同空檔，不寫入任何東西。

**參數**：`月份`、`時長分鐘`

**讀** `Availability Slots`（該月）、`Tasks`（排除已佔用的精準時間）、`Artists`

**與 `/從時間池建立任務` 的差別**：這支**不會**先整理時間池，所以不寫 Notion。

結果可分頁瀏覽（每頁以「整天」為單位切分）。除了上一頁／下一頁，還有跳頁下拉，標籤顯示該頁的**日期範圍**（例如 `9/13 – 9/16`）——控方找的是日期不是頁碼。

按「直接建立任務」可接到建立流程；按「關閉」則完全不留痕跡，並停留在目前翻到的那一頁。

`_overlap_query_pages()` 回傳 `(每頁文字, 每頁日期標籤)`；View 繼承 `paging.PagedTextView`，只額外加「直接建立任務」與「關閉」兩顆按鈕。

### `/從時間池建立任務`

從時間池找共同空檔並建立安排。

**參數**：`月份`、`時長分鐘`

**流程**

```
選藝人（可多選）
 └─ 系統先整理時間池 ← 會寫 Notion
     └─ 顯示候選時段（每頁 25 個，可翻頁跨頁勾選）
         └─ 選任務類型（選項即時讀自 Notion）
             ├─ 課程時間&作業繳交 → 課程類別 → 課程培訓 Project → 負責老師 → Modal 填課程名稱
             └─ 其他類型   → 選精準時間 → Modal 填地點等
```

**寫入一：時間池整理**（選完藝人時）
`Availability Slots`：合併重疊時段（更新 `可用開始時間`／`可用結束時間`）、封存冗餘資料、寫 `Audit Log`

**寫入二：建立 Task**（走到最後）

`Tasks` 新增：

| 欄位 | 值 |
|---|---|
| `任務名稱` | 控方填寫 |
| `任務狀態` | `尚未開始` |
| `任務類型` | 選擇的類型 |
| `關聯藝人` | 勾選的藝人 |
| 任務內頁 `任務說明` 區塊 | 候選時段等資訊 |
| `是否開放提交` | `false` |
| `Discord 顯示` | **`false`** |
| `課程類別`、`負責老師`、`關聯專案` | 課程流程才寫 |
| `開始日`、`截止日` | 有選精準時間才寫 |

**建立當下不通知任何人。** 回覆附 Notion Task 連結，控方補齊內容後自行勾 `Discord 顯示`。

### `/任務總覽`

列出所有未結案任務。**唯讀。**

分區同 `/我的任務`，另顯示藝人名。任務多時自動分頁，並提供跳頁下拉（標籤為該頁的分區名稱）。

### `/任務通知重送`

重新派發任務通知。**包含藝人已經按過「收到任務」的任務**——控方改了時間或內容後需要重發，是正常營運需求。

**參數**：`關鍵字`（選填）— 以任務名稱片段過濾，不分大小寫

**列出條件**：`Discord 顯示`=true 且狀態不在 `已完成`／`已取消`／`已封存`

選單會標示每筆的確認狀態（`⏳ 未確認` / `✅ 已確認`），未確認的排前面。

Discord 下拉硬上限 25 筆。超過時訊息會說明還有幾筆未列出，並提示改用 `關鍵字` 縮小範圍——控方要重送時通常已知道是哪一筆，用搜尋比翻頁實際，所以這裡不做分頁。

**流程**：選任務 → **二次確認** → 立即重送（不必等輪詢）

**寫** `Tasks`：清空 `Discord 通知時間`、`Discord 收到時間`

> 因為兩個時間欄位都會清空，**重送後藝人必須重新按一次「收到任務」**。這是刻意的：內容變更後的確認才有意義。

若任務沒有有效收件人（無關聯藝人或藝人缺 Discord User ID），系統會回報並不標記為已通知。

---

### `/審核提交`

審核待審核提交並通知藝人。

**流程**

```
選待審核提交（顯示 Drive 連結、文字內容、Notion 連結）
 └─ 選結果
     ├─ 通過   → Modal 填回饋（可空）
     └─ 需修改／退回 → Modal 填回饋 → 選 1～7 天修改期限
                       └─ 附批改檔？
                           ├─ 附批改檔 → 上傳或貼 Drive 連結
                           └─ 不需補批改檔
```

**寫**

`Submissions`：`審核狀態`、`審核回饋`、`審核者`、`審核來源`=Discord、通知成功後寫 `審核通知時間`

`Tasks`：
- 通過 → `任務狀態` = `已完成`
- 需修改／退回 → `任務狀態` = `需修改`、寫入 `修改期限`

批改檔歸檔至 `藝人專區/任務類型/YYYY-MM/YYYY.MM.DD_任務名稱/老師回饋/老師回饋_YYYY.MM.DD_ver.N/`，連結併入 `審核回饋`。

**Notion 直接審核也可以**：改 `審核狀態` 後，**至少填 `審核回饋`／`審核者`／`審核來源` 其一**，背景流程才會通知藝人。只改狀態不填任何回饋欄位視為歷史資料整理，不通知。

> 寫入失敗時先確認 Submissions 有這四個欄位：`審核回饋`、`審核者`、`審核來源`、`審核通知時間`。

### `/布告欄同步`

立即把 Notion 佈告欄同步到公告區（背景每 5 分鐘也會跑）。

**讀** 佈告欄：`Name`、`類別`、`狀態`、`Date`、`人員`、`📌 置頂`

新項目發成公告；內容或狀態變更會更新原訊息；沒變的不重發。訊息 ID 對應保存在本機 `.state/bulletin_sync.json`。

公告下方「回報／留言」按鈕，或直接回覆該公告，都會在佈告欄建一筆：`類別`=🙋 使用回饋、`狀態`=未處理，內容含 Discord 使用者與原公告連結。

同步目標依序：`BULLETIN_CHANNEL_ID` → `ANNOUNCE_CHANNEL_ID` → `SCHEDULE_CHANNEL_ID`。

### `/伺服器初始化`

建立或對齊六用途頻道與 `控方`／`藝人` 身分組。**只改 Discord，不碰 Notion。**

兩階段：預覽 → 按「確認初始化」才執行。既有同名頻道會沿用並更新分類、主題、權限。完成後回傳 `.env` 要填的 ID 清單，不直接改本機檔案。

也會同步 Discord Application Command Permissions，讓各頻道只顯示對應指令。

## 背景自動化

### 任務派發通知

**條件**：`Discord 顯示`=true、有 `關聯藝人` 或 `相關同仁`、狀態未結案、`Discord 通知時間` 為空

**動作**：私訊藝人（任務名稱、類型、截止日、任務內頁的任務說明）＋按鈕 → 寫 `Discord 通知時間`。每則帶按鈕的通知都記下訊息編號（`.state/task_notification_log.json`），藝人按「收到任務」時，同任務之前的通知全部改成「✅ 已收到」並拿掉按鈕

**相關同仁**（`相關同仁` relation → People）：收到同一份內容、拿掉交件指引、**沒有按鈕**。有藝人時，派發是否完成只看藝人（同仁失敗不會讓藝人重收）

`任務類型` 為 `PUBLIC_TASK_TYPES`（預設 `通告`、`演出`）時，私訊成功後另外發公告區。

首次啟用會先建立既有任務基準，不會一次轟炸歷史任務。背景也會清理「未勾 `Discord 顯示` 但殘留通知時間」的任務。

### 課後作業通知

**條件**：`Discord 顯示`=true **且** `是否開放提交`=true、有關聯藝人、未結案

**動作**：私訊「📚 課後作業通知」（作業要求、`提交期限`、交件指引）＋按鈕，寫 `Audit Log`

**每筆只發一次**，狀態存在本機 state 檔。

### 未確認任務重送

每 12 小時掃描未按「收到任務」的任務：先私訊未確認摘要，再逐筆重送完整通知。

### 批次重送（Notion 勾 `重送通知`）

每輪撈 `重送通知`=true 的任務：**先取消勾選再重送**（失敗也不會每輪重送），沒勾 `Discord 顯示` 或已結束的略過，結果彙整一則到控方頻道並寫 `Audit Log`。欄位不存在時整個功能靜默不啟動。

### 截止前提醒與逾期升級

**追蹤哪個日期**（`task_action_deadline`）：`需修改` → 只看修改期限；**`提前交件` ☑** → `提交期限`，沒填就 `截止日 − APPROVAL_LEAD_DAYS`（5）；`是否開放提交` ☑ 且有 `提交期限` → 提交期限；否則 → `截止日`。藝人看到的文字對應是「交件 M/D」或「截止 M/D」。

階段＝`DEFAULT_REMINDER_RULES`（`5 天前`、`3 天前`）**聯集** Task 的 `提醒規則`（`3 天前`／`1 天前`／`當天`），用 `<=` 比較，Bot 停機補跑仍會觸發一次。

- 勾選只能往上加，不能減少；只勾「逾期」**不再**能關閉事前提醒
- **去重寫檔**：已發的階段記在 `.state/task_notification_log.json`（key＝任務｜階段｜期限日），重啟不重發；改了期限會重新計算。首次啟用時窗口內的階段只記錄、不補發
- **`待審核`** → 不發截止前提醒（東西已交，球在公司）
- **截止前提醒的私訊**：含任務說明與交件指引，附 **[收到通知]** 按鈕（`ReminderAckButton`，custom_id `reminder_ack:<task>:<d5|d3|d1|d0>`，持久化）。送出時 Bot 先在 `提醒確認(From 藝人)` 寫一行 `階段｜時間｜已發送給 N 人`；藝人按了再追加 `階段｜時間｜藝人名`。同一輪多個階段一起到期時每階段各發一則、各一顆按鈕
- **逾期** → 不看規則一律觸發：私訊藝人（**無按鈕**）＋通知控方頻道＋`任務狀態` 寫成 `已逾期`。只靠這個狀態去重：控方改回 `進行中` 但沒延期，下一輪會再通知一次並改回 `已逾期`
- **相關同仁**：同一則提醒也私訊同仁（無按鈕、不算進「已發送給 N 人」）
- **不判逾期**：專案類型在 `NO_OVERDUE_PROJECT_TYPES`（課程培訓）的任務
- `/任務總覽` 每筆任務下顯示 `提醒確認（當天）：1/3 ✓（Johnny）`；藝人端 `/我的任務` 不顯示

### 每日催辦（`DAILY_NAG_HOUR`，預設 10:00）

- 一天一次，最後執行日存在 `.state/task_notification_log.json`；先記日期再發，失敗也不會同一天重試
- 藝人：`已逾期`、`需修改` 且 `Discord 顯示`=true 的任務，每人合併一則，不帶按鈕
- 審核人員：`待審核` 滿 `REVIEW_REMINDER_AFTER_HOURS`（24）小時，讀 Tasks `審核人員`，每人一則；沒填或聯絡不到 → 控方頻道
- 單則最多 20 筆，其餘註明筆數。取代舊的「每 12 小時催審」與「修改期限 24 小時前提醒」

### 修改期限逾時

過了 `修改期限` 還在 `需修改` → 通知控方一次（以期限為 key 寫檔去重，改期限會再通知）。

### 課後提醒老師

專案類型 `課程培訓`、課程結束（`截止日`；date-only 視為 23:59）滿 `TEACHER_REMINDER_AFTER_HOURS` → 私訊 `負責老師`；之後每天 `DAILY_NAG_HOUR` 再催，滿 `TEACHER_REMINDER_MAX_DAYS` 改通知控方一次並停止。**控方須手動檢查論壇貼文並將 Task 結案；Bot 不偵測論壇貼文。** 任務進入終態就停；結束超過 MAX_DAYS 的舊課不開始催。同課名＋同結束時間＋同老師的多筆任務合併一則。老師沒有 Discord ID 或私訊失敗 → 控方頻道。

### 發文待確認發布彙整

每週 `PUBLISH_CONFIRM_DIGEST_WEEKDAY`（預設週一）`_HOUR`（10）點，在控方頻道發一則：專案類型 `月度排程 （發文）`、狀態 `已完成`、截止日已過 `_AFTER_DAYS`（3）天的任務。沒有就不發。

### 月度排程公告

隨布告欄同步（5 分鐘）。公告頻道每月一則，列出當月（`開始日`，沒有就 `截止日`）、`Discord 顯示`=true、不是已取消／已封存、類型在 `PUBLIC_TASK_TYPES` 的任務；內容指紋不含更新時間，沒變不編輯；訊息被刪就重發，**即使內容指紋未變也會復原**。狀態存在 `.state/monthly_board.json`。

### 月度時間池與排課 SLA

- 收集截止前催未填藝人、截止後通知控方
- 流程超過 `SLA_HOURS`（48）小時升級、`SLA_HARD_LIMIT_HOURS`（72）小時提示候選可能失效
