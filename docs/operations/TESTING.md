# 測試與驗收

這份文件給工程師、AI 協作者與控方測試 Bot 使用。  
測試分成三層：本機自動測試、Discord 手動驗收、Notion 資料驗收。

## 本機自動測試

### 語法檢查

```bash
.venv/bin/python -m compileall bot.py cogs services tests config.py web
```

### 單元測試

```bash
.venv/bin/python -m pytest tests/ -q
```

2026-08-08 本機基準：`282 passed`；正式 Notion 唯讀 smoke test 讀取 9 個 Data Source 全數通過。

目前測試重點：

- 設定載入。
- Discord command 權限與頻道限制。
- 月度時間收集日期 / 週次邏輯。
- Availability Slots 去重、合併、封存規則。
- Tasks / Projects 對排程的影響。
- 共同時段交集演算法。
- 時間字串解析。
- 會議秘書小律的權限、資料範圍白名單、個人與系統可選 token 護欄、問題回報。
- Discord 伺服器初始化規格、env 清單與管理指令權限。

## 啟動驗收

啟動：

```bash
.venv/bin/python bot.py
```

啟動成功應看到：

- Slash commands synced to guild。
- Discord gateway connected。
- Bot logged in。
- Notion smoke test 成功。
- Console 顯示可排課藝人數量。

啟動時 Bot 會：

- 讀 `Artists`。
- 寫一筆 `Audit Log`。

如果 Notion smoke test 失敗，先檢查：

- `.env` 的 `NOTION_TOKEN`。
- Notion integration 是否有資料庫權限。
- Data Source ID 是否正確。
- Artists 是否至少有可排課藝人。

## Discord 手動驗收

### 頻道限制

正式配置有六個用途頻道：`公告區`、`時間管理`、`任務查詢入口`、`課程助教`、`營運內部通知`、`營運操作`。

驗收：

1. 在 `時間管理` 執行 `/管理可配合時間`，應可正常進入管理 UI。
2. 在 `任務查詢入口` 執行 `/管理可配合時間`，應提示回到時間管理。
3. 在 `任務查詢入口` 執行 `/我的任務`，應可正常查詢。
4. 在 `時間管理` 執行 `/我的任務`，應提示回到任務查詢入口。
5. 在 `營運操作` 執行 `/從時間池建立任務`、`/任務總覽`、`/任務通知重送`、`/審核提交`、`/布告欄同步`，應可正常進入。
6. 在 `任務查詢入口` 執行上述管理指令，應提示回到營運操作。
7. `/伺服器初始化` 僅限管理員；為支援首次建立頻道，程式不硬性限制既有頻道。

### 伺服器初始化

1. 由管理員執行 `/伺服器初始化`。
2. 未按「確認初始化」前，不應建立或修改任何頻道。
3. 確認後應建立／沿用 `控方`、`藝人`，以及六用途頻道。
4. 未指派身分組的測試帳號不應看到營運區。
5. 藝人可看公告／時間／任務／課程助教，但不能看營運內部通知。
6. 重新執行 `/伺服器初始化` 並確認後，檢查各頻道的 slash command 選單只顯示該頻道允許的指令。
6. 公告區藝人不能發言；控方與 Bot 可以發送。
7. 將回傳 ID 填入 `.env`、重啟，再依 [SERVER_MIGRATION.md](SERVER_MIGRATION.md) 設定 slash command UI 可見性。

注意：

- 程式層會阻擋錯頻道執行。
- 若要讓錯頻道完全看不到指令，需要到 Discord App / Integration 設定 command permission。

### 月度時間收集

驗收流程：

1. 控方在 `營運操作` 執行 `/時間資訊蒐集 月份:YYYY-MM 截止天數:1`，月份使用尚未結束的測試月份。
2. Bot 應在公告區發公告並 mention 藝人。
3. 藝人點公告按鈕或執行 `/管理可配合時間 月份:YYYY-MM`。
4. 藝人跨分頁選擇第一批日期與時間，按「加入本次回報」。
5. 確認 Notion `Availability Slots` 尚未新增資料，再加入第二批不同日期與時間。
6. 按「管理全部已選」，單選第一組後按「修改選取」；確認下一層列出該組內的每個日期。
7. 選其中一天按「修改單日」，修改時段並儲存；確認該日被拆成新組，同組其他日期仍保留原時段。
8. 按「修改整組」可修改整組日期與時段；按「取消修改」時原組保持不變。
9. 在管理頁多選錯誤組別並移除；重新開啟同月份入口時應接續剩餘草稿。
10. 按「檢查全部時段」，確認總覽列出所有組別的實際寫入時段。
11. 按「全部確認送出」後，Notion `Availability Slots` 才一次新增整批資料，控方收到個別完成通知。
12. 全員完成後，控方應收到可執行 `/從時間池建立任務` 的通知。
13. 建立一筆 `8/15 13:30–14:30` 的正式 Task，讓藝人選 `8/15 整天可`；確認整批總覽顯示 `08:00–13:30`、`14:30–24:00`，並可返回調整。
14. 再提交完全重疊的 `8/15 13:30–14:30`；確認 Bot 顯示整段被占用，且停用整批送出按鈕。
15. 勾選本月已過去的日期；確認整批總覽在「已略過過去時段」中逐筆說明，且不寫入 Notion。

驗收重點：

- 日期分頁正常。
- 今天以前的日期不出現在選單；今天與未來日期仍可選。
- 可以多天套用同一時段。
- 不同日期可分成多個時段組別，最後一次送出。
- 可以回頭修改任何暫存組或組內單日；修改單日不影響同組其他日期。
- 取消本次回報會清除暫存且不寫入 Notion。
- 已正式安排的衝突時段會被切掉，不會整天封鎖。

### 藝人刪除重填

驗收流程：

1. 藝人執行 `/管理可配合時間`，不填月份。
2. 從總覽選擇月份，再選擇要刪除的時段。
3. Bot 應 archive Notion `Availability Slots` 對應 page。
4. 在同一入口按「新增／補填日期」。
5. 重填正確時段。

驗收重點：

- Discord 顯示的刪除與 Notion archive 一致。
- 刪除後不需要控方重發公告。
- 新資料會正常出現在 `/管理可配合時間` 的跨月份總覽。

### 時間池整理

驗收流程：

1. 建立幾筆重複或重疊的 availability。
2. 藝人按填寫流程的「完成」，確認 Bot 自動整理該藝人的時間池。
3. 再執行 `/從時間池建立任務`，確認比對前會再次整理被選藝人的最新資料。
4. Notion 應保留較寬時段並 archive 冗餘資料。

驗收重點：

- 不應直接硬刪 page。
- 套用後寫 `Audit Log`。
- 不再提供獨立 `/時間池整理` 指令或人工套用按鈕。

### 時間池比對

驗收流程：

1. 至少兩位藝人填同月份 availability。
2. 控方執行 `/從時間池建立任務 月份:YYYY-MM 時長分鐘:60`。
3. 選兩位以上藝人。
4. Bot 應列出共同時間窗與可開始時間。

驗收重點：

- 只讀 `Availability Slots` 中符合月份的月度可配合時間。
- 正式 Tasks 精準時間會先扣除。
- 若有人未填，結果會列出未填藝人。
- 時長顯示用小時，例如 `240 分鐘` 顯示為 `4 小時`。

### 任務查詢

驗收流程：

1. 在 Notion `Tasks` 建立任務。
2. 關聯藝人。
3. 勾選 `Discord 顯示`。
4. 藝人在 `任務查詢入口` 執行 `/我的任務`。
5. 控方在 `營運內部通知` 執行 `/任務總覽`。

驗收重點：

- 未勾 `Discord 顯示` 的任務不出現在藝人 `/我的任務`。
- 已完成、已取消、已封存任務不應列入未結案。
- 待審核任務顯示為公司確認中，不應對藝人顯示逾期。

### Drive 歸檔真人驗收（M4-07）

**隔離規則：不得拿正式藝人或正式任務做 Drive 歸檔 QA。**

1. 優先使用 Artists 中明確標示為測試的帳號；目前可用的是 `Chenhua（測試）`。它的用途只是提供獨立的 Discord 帳號與 Drive 專區，和任何正式藝人、客戶案件沒有業務關係。
2. 測試新建的 Project、Task、Submission、Drive 資料夾與檔案名稱，一律加前綴 `QA M4-07` 並包含測試日期，例如 `QA M4-07 Drive Archive 2026-10-18`。
3. 測試檔只可用無敏感資料的純文字或空白檔；不得上傳藝人作品、客戶素材、合約或個資。
4. 至少驗證：有專案路徑、`未分專案` 路徑、同任務 `ver.1`／`ver.2`、`老師回饋` 子資料夾、Task 的 `Google Drive Folder` 回寫，以及 Submission 的檔案類型優先序。
5. QA 產物預設保留，作為驗收證據；如要清理，先在任務卡記錄驗收結果，再由控方明確決定 archive／刪除範圍。

### 任務提交

驗收流程：

1. 在 Notion `Tasks` 建立任務。
2. 關聯藝人。
3. 勾選 `Discord 顯示` 與 `是否開放提交`。
4. 藝人在 `任務查詢入口` 執行 `/我的任務` → `提交任務`。
5. 選任務後，Bot 應直接給這次提交的公司 Drive 資料夾與「我已上傳到 Drive」。
6. 成功提交後，Notion `Submissions & File Index` 應新增一筆，Task 應轉為 `待審核`。

驗收重點：

- 不論 Notion `提交方式` 填什麼（或欄位已刪除），都只走公司 Drive 上傳；不得出現貼連結或填文字的表單（2026-10-11 起，M4-03）。
- 任務清單與通知不應再出現「提交方式：…」。
- 藝人在 Discord 直接附加作業檔時，Bot 應拒絕並引導回指定 Drive 資料夾。

### 課程結束後開放作業

驗收流程：

1. 建立一筆 `任務類型=課程時間&作業繳交` 的 Task，關聯藝人，勾 `Discord 顯示`，但不要勾 `是否開放提交`。
2. 確認藝人收到課程通知，且沒有被要求提交作業。
3. 在同一筆 Task 補上作業要求、`審核人員` 與 `提交期限`；保留原本課程的 `開始日／截止日`。
4. 最後勾選 `是否開放提交`，確認課後作業通知顯示 `提交期限`，而不是課程結束時間。
5. 測試環境等待最多 30 秒（`REMINDER_INTERVAL_MINUTES=0.5`）。
6. 確認藝人收到一次「課後作業通知」，內容包含作業要求與交件指引。
7. 確認 `Audit Log` 有紀錄；重新掃描或重啟 Bot 不應重複發送。
8. 再測一筆保持 `是否開放提交=false` 的 Task，確認不會提前通知。

驗收重點：`是否開放提交` 是第二階段 trigger，不需重新建立 Task；課後作業通知只發關聯藝人私訊。

### 提交審核

驗收流程：

1. 先完成一筆 `/我的任務` → `提交任務`，確認 Submissions 狀態為 `待審核`。
2. 控方在 `營運內部通知` 執行 `/審核提交`。
3. 選該筆提交。
4. 測試 `通過`：填回饋，確認藝人收到 DM，Task 轉 `已完成`。
5. 另建一筆提交，測試 `需修改` 或 `退回`：確認藝人收到 DM，Task 轉 `需修改`。

驗收重點：

- Discord 審核會寫入 `審核狀態`、`審核回饋`、`審核者`、`審核來源`、`審核通知時間`。
- Notion 手動審核時，只改狀態但沒有回饋／來源不應通知；補上 `審核回饋` 或 `審核者` 後，背景 loop 應通知藝人。
- 若 Discord 顯示「審核寫入 Notion 失敗」，先檢查 `Submissions & File Index` 是否已新增
  `審核回饋`、`審核者`、`審核來源`、`審核通知時間` 四個欄位。

### 任務提醒

驗收流程：

1. 建立一筆有截止日與提醒規則的 Task。
2. 等待 reminder loop。
3. 藝人應收到 DM。
4. 逾期時，Task 狀態應更新為 `已逾期`。
5. 控方應在任務查詢入口收到逾期通知。

驗收重點：

- 截止前提醒一律有 5 天前、3 天前，`提醒規則` 勾的再加。
- **重啟 Bot 後，已發過的截止前提醒不應重發**（M3-23，紀錄在 `.state/task_notification_log.json`）。
- 逾期提醒不看提醒規則，一律觸發。
- 已逾期狀態持久化在 Notion，Bot 重啟後不應重複升級同一筆。
- 把已逾期的任務改回 `進行中`、不改期限 → 下一輪應再通知一次並改回 `已逾期`（M2-13）。

### 收到任務後舊通知標為已收到（M3-23）

1. 對同一筆任務讓藝人收到兩則以上通知（派發＋`/任務通知重送`，或等未確認重送）。
2. 藝人在最新一則按「收到任務」。
3. 預期：**所有**該任務的舊通知都變成「✅ 已收到（月/日 時:分）」、按鈕消失；其他任務、其他藝人的訊息不受影響。
4. 先手動刪掉其中一則舊通知再按，流程仍應成功（略過被刪的那則）。

### 每日催辦（M3-11）

1. 準備一筆 `已逾期`、一筆 `需修改`（同一位藝人），以及一筆 `待審核` 超過 24 小時、有填 `審核人員` 的提交。
2. 等到 `DAILY_NAG_HOUR`（預設 10:00）後的第一輪。
3. 預期：藝人收到**一則**合併兩筆的提醒、沒有按鈕；審核人員收到一則待審清單；同一天重啟或再跑一輪都不重發。
4. 審核人員沒填或沒有 Discord ID → 清單發到 `營運內部通知`。

### 課後提醒老師（M5-01）

1. 建一筆專案類型 `課程培訓` 的任務，`截止日` 設成 3 小時前、填 `負責老師`（People 有 Discord ID）。
2. 等一輪：老師應收到「📝 課後提醒」，含學生與上課時間。
3. 同一堂課建第二位學生的任務（同名、同時間、同老師）：老師仍只收到一則，學生名單合併。
4. 把任務改成 `已完成`：隔天 10:00 後不應再提醒。
5. 老師沒有 Discord ID：提醒改發到 `營運內部通知`。

### 相關同仁收通知（M6-05）

前提：Tasks 已建立 `關聯藝人`（relation → Artists）及 `相關同仁`（relation → People）。兩欄共同構成「任務相關對象」，不可改用單一 `相關人士` 欄位。

1. 建一筆新的測試 Task，填一位有 Discord ID 的同仁、勾 `Discord 顯示`、保持未結案 → 同仁收到通知，開頭是「👥 同仁知會」，沒有按鈕、沒有交件指引。
2. 同時掛一位藝人與一位同仁 → 兩人都收到；只有藝人那則有按鈕。按藝人的「收到任務」後，任務可轉為 `進行中`；同仁沒有可操作按鈕。
3. 同仁缺 Discord User ID 或私訊失敗 → 藝人的派發與確認仍正常，不得造成藝人重收。
4. 兩人收到的訊息都不得有 Notion 網址（任務說明貼一個 Notion 網址測試）。

### 任務內頁＝任務說明（M7-07，2026-10-21）

1. 測試任務的內頁直接寫兩段文字（不加標題），重送通知 → 派發私訊的「任務內容」是這兩段；小律問這筆的詳細內容一樣。
2. 內頁加一個切換清單、一個兩欄分欄、一個兩列表格，各放一句 → 三句都出現在通知裡，表格顯示成「欄｜欄」。
3. 內頁加一個子頁面，子頁面裡寫「內部」→ 通知裡沒有「內部」。
4. 內頁貼一個 Notion 網址和一個 YouTube 網址 → 藝人通知只有 YouTube。
5. 藝人按「有問題」填原因 → 內頁多一段「藝人回覆」；重新派發後，通知不含這段原因。
6. 內頁清空 → 通知寫「Notion 尚未填寫任務說明」。
7. 總表的 `任務說明` 欄位刪掉後（或改填欄位）→ 通知內容不受影響。

### 批次重送（M3-22）

前提：Tasks 已建立 `重送通知`（Checkbox）。勾兩筆已派發任務 → 下一輪藝人重收通知、勾選自動取消、控方頻道收到一則摘要。

### 月度排程公告（M6-02）

1. 建一筆本月、`任務類型=通告`、勾 `Discord 顯示` 的任務 → 5 分鐘內公告區出現「🗓️ 本月排程」。
2. 改名稱或日期 → **還是同一則訊息**，內容更新。
3. 把類型改成 `錄音` → 從排程消失。
4. 內容不得有 Notion 網址。
5. 不改 Notion 資料，手動刪除月度公告 → 下一輪（最多 5 分鐘）應自動補發一則；再等一輪不得重複補發。

Drive 資料夾回寫驗收：

- 單一藝人任務首次 Drive 提交後，Tasks 的 `Google Drive Folder` 應自動出現任務資料夾連結。
- 多人任務首次提交後，任務內頁應出現「Drive 資料夾索引」段落及藝人對應連結；同一藝人再次提交不可重複追加。

### 目前安排流程驗收

驗收流程：

1. 控方執行 `/時間資訊蒐集`，藝人填寫月度可配合時間。
2. 控方執行 `/從時間池建立任務`，選月份、時長與多位藝人，確認共同空檔。
3. 選「課程」後選課程類別、課程培訓 Project、老師與名稱，確認 Bot 建立一筆 Tasks。
4. 在 Notion Tasks 的 `課程時間&作業繳交` 補課程類別與正式開始／截止時間，確認可作為正式佔用判斷。
5. 選「錄音／通告／其他」時，確認 Bot 建立 `Discord 顯示=false` 的 Task 草稿，且藝人未收到通知。
6. 在 Task 補齊內容、地點與正式時間後勾選 `Discord 顯示=true`，確認 Bot 自動通知藝人。
7. 確認藝人 DM 與 Audit Log；再次使用任務通知重送時，只重送尚未確認的藝人。
8. SLA 的 24／48／72 小時情境使用 `tests/test_scheduling_sla.py` 的模擬時間驗證，不需真等候。

舊 `/排課建立`、`/排課比對`、`/排課確認`、`/排課狀態` 與其 Schedule Request／Course Session 程式已完整刪除。老師確認表單流程已移除；老師時段改為人工協調後由控方直接在 Notion Task 填正式時間。

### 任務派發與收到確認

1. 確認 Bot 已完成第一次背景 loop，既有任務不會被重新推播。
2. 在 Notion 建立新 Task，關聯測試藝人、勾選 `Discord 顯示`，狀態設為 `尚未開始`。
3. 等待提醒 loop，確認藝人收到私訊，內容包含任務名稱、截止日與任務說明。
4. 藝人按「收到任務」，確認 Task 狀態變成 `進行中`。
5. 確認 Tasks 的 `Discord 收到時間` 與 Audit Log 有紀錄。
6. 重新啟動 Bot 後確認同一任務不會重複發送通知。
7. 用另一位藝人點擊按鈕，確認 Bot 拒絕非關聯藝人的操作。

### 藝人回報問題後重新派發

1. 建立一筆測試 Task，關聯測試藝人、狀態設為 `尚未開始`，並勾選 `Discord 顯示`。
2. 等待藝人收到通知，確認 `Discord 通知時間` 已寫入。
3. 藝人按「有問題／無法配合」，填寫原因並送出。
4. 確認 Task 變成 `尚未開始`、`Discord 顯示` 取消，兩個 Discord 時間欄位皆清空；回饋已追加到任務內頁的「藝人回覆」段落。
5. 確認控方頻道收到回報原因與 Notion Task 連結。
6. 控方修改任務後重新勾選 `Discord 顯示`。
7. 等待一輪 `REMINDER_INTERVAL_MINUTES`，確認藝人收到新的完整通知與按鈕。
8. 藝人按「收到任務」，確認狀態轉為 `進行中`，且不再出現在 `/任務通知重送` 清單。

審核結果驗收（藝人端零 Notion 入口）：

1. 對一筆有關聯 Task 的 Submission 執行 `/審核提交`，選擇 `需修改` 或 `退回`。
2. 確認藝人 DM **完全不含任何 Notion 連結**，且包含任務名稱、審核結果、老師回饋與「到 `/我的任務` 重新提交」的指引。
3. 老師補上批改檔後，確認補充通知同樣不含 Notion 連結，但 **Drive 批改檔連結要保留**（那是藝人該拿到的）。
4. 控方端對照：`/審核提交` 的提交詳情**仍會**顯示 Notion 連結，控方有 Notion 權限，不受此限。
5. 審核完成後按「不需補批改檔」，確認「附批改檔」與「不需補批改檔」都從訊息消失，不能再開第二條流程。
7. 使用一筆舊的、缺少 `關聯任務` 但原 Task `最新提交 URL` 正確的 Submission，確認「附批改檔」仍能產生公司老師回饋資料夾。

### 會議秘書小律驗收

1. 確認 `Artists` 有 Discord User ID，且會議紀錄關聯該藝人、`會議類型` 不在 `QA_HIDDEN_MEETING_TYPES` 排除清單內（KariKari 排除 `課程`／`課程會議`）、`藝人可見` 已勾選。
2. 在 `AI_CHANNEL_ID` 直接輸入問題，確認 Bot 建立本人私人 Thread；其他藝人不能在該 Thread 讀取資料。
3. 若會議頁有 PDF／DOCX／PPTX／XLSX，確認第一則回覆先顯示會議附件索引，且仍會處理當次問題；未指定附件時不引用附件正文。
4. 指定會議頁或檔名後提問，確認回答只引用指定附件與允許的會議正文，並附 Notion 來源。
5. 連續追問，確認沒有 15 秒冷卻限制；長回答會分成多則 Discord 訊息。
6. 更新 Notion 會議內容後再次提問，確認 Bot 重新讀取最新內容。
7. 暫時移除 `管理訊息` 權限後提問，確認 Bot 不在公開頻道顯示權限警告，仍嘗試建立私人 Thread。
8. 未設定 `LLM_API_KEY` 或模擬 API timeout，確認使用者收到明確錯誤，而不是未處理例外。
9. 將測試藝人設為 `未簽`、`暫停` 或 `封存`，確認無法使用小律；`已簽約`、`洽談中` 可使用。
10. 目前 `LLM_DAILY_TOKEN_LIMIT` 與 `LLM_PER_ARTIST_DAILY_TOKEN_LIMIT` 預設皆為 `0`（不限額）。需要驗證護欄時，暫時將個人值設低，確認額度用完只限制該藝人；測試後恢復為 `0`。
11. 按回答下方 `回報問題`，確認 Notion 布告欄新增 `🙋 使用回饋`，且頁面不含原始問題全文。
12. 送出模糊問題，確認 Bot 要求補充範圍，不會直接回答前幾筆會議紀錄。
13. 連續快速送出兩個問題，確認同一位藝人的請求依序完成，沒有互相覆蓋回答。
14. 模擬 LLM timeout／網路錯誤／5xx，確認 Bot 最多自動重試一次；模擬空白或錯誤 JSON，確認顯示明確失敗訊息。
15. OpenAI 環境確認 `LLM_BASE_URL=https://api.openai.com/v1`、`LLM_MODEL=gpt-5.6-luna`；用簡短問題確認呼叫 `/v1/chat/completions` 並回傳完整答案。
16. 將 URL 或模型名稱暫時設成 LongCat，確認系統在發出網路請求前拒絕，並顯示供應商設定不受支援；測完立即恢復 OpenAI 設定。
17. 建立一筆 `會議類型=課程` 的紀錄並勾選 `藝人可見`，確認小律仍然查不到它——排除清單優先於藝人可見。

## Notion 驗收

### Artists

可排課藝人需符合：

- 有 `Discord User ID`。
- `合約狀態` 不是 `暫停` / `封存`。

### Availability Slots

驗收：

- 月度時間池 slot 不再使用 `關聯排課需求` 欄位。
- 備註包含 `收集月份：YYYY-MM`。
- 刪除時 page 應 archive。
- 重複或冗餘資料整理後不應留在可見清單。

### Tasks

驗收：

- `Discord 顯示` 控制藝人是否看得到。
- 硬性佔用類型有明確開始 / 結束時間時，會切掉 availability。
- 非硬性任務只提醒，不封鎖整天。

### Audit Log

重要操作應有紀錄：

- Bot 啟動。
- 建立月度收集。
- 藝人提交 / 刪除時間。
- 時間池整理。
- 時間池比對（`/從時間池建立任務`）與唯讀交集查詢（`/時間交集查詢`）。
- 候選超過 25 個時，確認 Discord 可分頁查看全部候選，跨頁選擇後仍能一次送出。
- 任務逾期升級。

### 文件與指令清單

- 程式目前應註冊 10 個 slash commands。
- [DISCORD_CHANNELS.md](DISCORD_CHANNELS.md) 與 [DISCORD_COMMANDS.md](DISCORD_COMMANDS.md) 應包含全部 10 個，且 `/任務通知重送` 位於營運操作。
- `/提交任務` 與 `/課程問答` 不應再出現在 Discord 指令選單；提交由 `/我的任務` 內的按鈕進入，會議秘書小律使用指定頻道自然對話。
- Markdown 的相對連結應全部指向存在的檔案。

## 常見問題排查

### 指令出現但執行後提示錯頻道

這是正常行為。程式層會阻擋錯頻道執行。  
要讓指令在錯頻道不出現，請設定 Discord App / Integration command permission。

### 藝人查不到自己

檢查：

- Artists 是否填 `Discord User ID`。
- Discord User ID 是否是純數字。
- `合約狀態` 是否為 `暫停` / `封存`。

### `/從時間池建立任務` 沒結果

檢查：

- 月份是否正確。
- 藝人是否有填該月份。
- availability 是否被有明確時間的正式 Tasks 扣掉。
- `時長分鐘` 是否太長。

### Notion 互動慢或 Discord 顯示互動失敗

檢查：

- Notion API 是否延遲。
- 指令是否有先 `defer()`。
- autocomplete 是否使用快取。
- 是否一次查太多資料。

## 全流程返回鍵驗收

1. 開啟 `/管理可配合時間`，選日期與時間後按「加入本次回報」；Notion 不應新增時段。
2. 加入第二組後按「檢查全部時段」，再按「全部確認送出」，Notion 才應一次新增整批時段。
3. 在 `/管理可配合時間` 選取既有時段時不得立即刪除；按「刪除選取時段」後才封存。
4. 執行 `/我的任務` → `提交任務`，選任務進入公司 Drive，確認可返回任務清單。
5. 執行 `/審核提交`，進入一筆提交後按「返回審核清單」，確認可重新選擇。
6. 執行 `/從時間池建立任務`，逐層測試返回藝人、候選時段、任務類型、課程類型與 Project。
7. 執行 `/任務通知重送`，只選任務不得執行；按「確認重送」後才清除通知時間。
8. 在任何第一層按「取消」，確認 Discord 結束操作且 Notion 沒有變更。
